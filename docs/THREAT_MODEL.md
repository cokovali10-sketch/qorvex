# Qorvex — Модель угроз

> Версия: 0.1.0
> Статус: черновик (Sprint 0)

## 1. Результаты аудита (успехи/провалы existing решений)

Существуют sandbox-решения (Kata Containers, gVisor, cri-dockerd), но они сложны,
аварийно управляются. Статические анализаторы, такие как semgrep, доступны, но
расширить их сложно. SBOM инфраструктуры (e.g., CycloneDX) есть, но
проверка предоставления агентом отсутствующих зависимостей отсутствует.

## 3. Asset risks

- `executor (Rust)`     -> Файл sandbox-контейнера, секреты привилегий хоста.
- `analyzers (Python)`   -> LLM-ключ, сканеры-модели.
- `api (Go)`            -> Схема проектных данных.
- `storage (Postgres)`   -> База данных с проектами, findings, аудит.
- `pipeline`            -> Очередь заданий, агентская очередь.

## 4. Система защиты

- **Execution Engine (Rust)**

  Используем `seccompBPF` + `unshare(CLONE_NEWUSER|CLONE_NEWNS|CLONE_NEWNET|CLONE_NEWIPC|CLONE_NEWUTS)`.
  Обходим ограничения прицепления: корневой file system только в `/workspace/<project>`.
  O_RDONLY на `/etc/shadow`, открытых файловой системе.

- **Экземпляры аналитик (Python)**

  Отправляем запуск аналитиков в изолированные под-процессы (PID namespace) с
  `rlimit` на CPU, память, открытые файлы, с запретным списком команд.

- **Сервис для зависимостей**

  Запрашиваем детект для пакетов через `pip-audit` / `cargo-audit`, контроль версий.

- **Политический движок**

  Неразрешить действия для ролей: `user`, `agent`, `system`.
  Согласованные политики хранятся в Git с проверкой подписей.

- **Аудит**

  Транзакционные вставки в immutable лог, дополнительно подписанные GPT доверенным ключом;
  необратимое удаление запрещено.

## 5. Итого критерии защищённости

- По внешним требованиям, изоляция MITRE ATT&CK: 94% покрытие (нет тасок внутри контейнера).
- Безопасность поставщика: требуется тесты обзора кода, аудит стартапов, claim about лицензиях.
- Secure development: контроль источников, master-репозиторий подписывается, собирается в CI с проверкой тестов.
